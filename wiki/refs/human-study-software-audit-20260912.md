# MindOS human study 软件就绪审计

日期：2026-09-12。范围：现行研究代码、参与者/研究者/评审组件、运行日志、局部测试；对照 `paper/figures/empirical/FIGURE_PLAN.zh.md`。这是实现审计，不是正式实验结果或完整 UI 验收。

## 结论

已有可复用的研究基础，缺口主要是不同研究流程的整合、参与者生命周期和证据链。当前多轮运行器检验的是受限的方法更新机制，尚不等同于论文的完整 shared mind / human–agent co-evolution 实验。应先修运行和数据正确性，再形成一条可复现的试验流程，不扩张普通产品菜单。

## 已实现的能力

- 四阶段研究（research v1）：基线、辅导、迁移、延迟保持；任务时间预算、信心/外部辅助等记录；参与者邀请和独立在线评审。
- 多轮研究（longitudinal v2）：协议冻结与哈希、2–6 轮、两种方法生效策略的平衡分配、独立作答→辅导→独立迁移、更新窗口、审核、下一轮生效和冻结方法组、轮间等待。
- 多轮参与者专属访问、知情确认、答案锁定、阶段信息隔离、失败记录、帮助预算、幂等/版本冲突控制、7 天本地草稿。
- 研究者进度及待审核看板；原始 JSON、盲评材料和研究者映射导出。
- 日常方法检验、版本对比和跨 Agent 交接另有实现；这些产品功能不能直接视为受控实验的替代。

## 研究流程需要整合的能力

### 1. 把多轮与最终延迟测量接成一个协议

v2 最后一轮第三次作答后直接 complete；delayHours 控制轮间等待，并非最后一次延迟保持。v1 虽有 delayed，但并未与 v2 共享一条完整阶段流。

验收：同一参与者、协议和分配贯穿多轮及延迟无辅助测验；记录实际间隔、开放窗口、逾期/缺失原因；关闭浏览器后能回到准确阶段。若首轮仅验证两轮可用性，可明确暂不纳入延迟终点，不能据此报告保持效果。

### 2. 独立评估双方变化，并控制两个影响方向

v2 模型请求仅含批准的方法字符串、当前任务和当前问题，明确禁用外部记忆与工具。这是清楚的受限机制，但并非对 MindOS 全部偏好、目标、经历与共享知识的实验。

现有 next-round/frozen 主要控制人的方法更新能否进入后续 Agent 帮助。正式支持论文 Fig. 2–3 还需：

- 人：独立迁移与延迟测量。
- Agent：固定运行配置的未见任务探针，不用辅导对话的表现替代。
- 两方向：分别指定更新/反馈可用性、生效轮次和实际送达记录，连接到后续独立测量。
- 对照：按照最终协议加入信息和预算匹配的普通共享文档、Agent 记忆等条件；不靠提示词标签冒充不同记忆机制。

先明确纳入实验的共享状态范围，再实现对应快照与注入接口；不要求把日常知识库所有能力都塞入第一轮试验。

### 3. 合并评分与分析所需记录

v1 有在线评审，v2 只有导出包。可先采用冻结包的线下独立评分，但须稳定关联题目、答案、评分人及评分版本；之后复用在线评审，不必另造系统。

v2 答案主要记录 stage/answer/提交时间，缺少逐阶段打开/作答耗时、明确的辅助使用标记、跳过/超时/缺失原因。模型执行器保存输出与运行身份，但没有保留 provider usage。因此现有时间戳能估算部分运行延迟，不能当作人的有效投入时间或完整模型成本。

建议最小导出：participant、condition、protocol、round、task/item/family、stage、assessment、snapshot、run、assistance、时间/缺失原因、评分和版本。仅在研究确实分析维护负担/成本时再补精确的活动时间及 usage 字段，避免无目的采集。

### 4. 将交接与情境变化作为明确的扩展实验

日常交接已有来源、目标、方法快照、案例与核对记录，但常规工具和上下文仍可生效。论文 Fig. 4 所需的同一替换 Agent、无继承/共享文档对照、匹配预算、独立测验尚需进入研究协议。

Fig. 5 的情境变化、有效/过时记录、信号出现时间、错误采纳/正确拒绝与恢复窗口也应是预先冻结的任务安排。可以在核心试跑后补，不要求第一批可用性参与者同时完成所有扩展。

## 界面收敛建议

- 参与者入口只围绕当前任务：当前轮次/阶段、是否允许辅助、保存状态、下一步与何时回来；复用现有研究页面，避免让参与者自行穿梭产品菜单。
- 初始读取应显示明确 loading，不能在 view 为空时先显示“需要私人链接”；分清正在保存、已保存、结果未知、需要重试。
- 多轮参与者已有本地草稿，但 v1 作答、评审及研究者方法审核仍有仅内存状态。补刷新/重开恢复，以及“查看已保存状态后重试”的完整路径。
- 等审核/等下一轮时给出返回时间和恢复入口。自动提醒按试验需要选择，首轮也可研究者人工联系，不必先建通知平台。
- 共享经验只在协议允许的协作/反思阶段可见，展示内容、来源及生效状态；独立测验继续隐藏帮助，不能为了展示产品概念破坏阶段隔离。
- 方法审核界面现在显示所属策略；若审核判断无需条件身份，默认隐藏，减少差别对待风险。
- 当前浏览器被运行错误阻塞，不能确认中文手机端视觉质量。修复后必须实际走完“进入→同意→作答→失败重试→跨天恢复→退出/删除”，并验收材料导出与评分关联。

## 推荐交付顺序

1. 页面运行稳定 + 退出/删除 + 邀请管理 + 稳定评分快照。
2. 一条统一的参与者流程，补关键记录及恢复体验，使用真实模型做完整内部彩排。
3. 小规模真人可用性试跑：验证能独立完成、可恢复、数据能评分；不用于证明共同进化效果。
4. 根据试跑冻结正式协议，补独立 Agent 探针、双向干预、强对照及必要的交接/情境变化扩展。
